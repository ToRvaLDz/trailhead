# Debug (scientific method)
A bug is a science problem: observe, hypothesize, test, confirm, verify. Never patch on a hunch: an unconfirmed fix is a guess that recurs. Treat the issue as persistent debug state: log every hypothesis, test, and eliminated cause as comments, so a context reset never restarts the investigation.

**Redact as you go.** These notes are posted on public Issues. When you show a command, output, or artifact, replace every secret with `<REDACTED>` and run loops against env vars, never inlined credentials; quote only the signal-carrying lines, not whole dumps. If a redacted artifact isn't enough to move forward, say so and ask the user; never paste the raw one to compensate.

1. **Reproduce: build a feedback loop.** Get ONE command you've actually run that goes red on *this exact symptom* and green when fixed: a failing test at the nearest seam, a curl against a dev server, a CLI diff vs a known-good snapshot, a replayed trace. Tighten it: faster, sharper (assert the specific symptom), deterministic (pin time, seed RNG, freeze network). No red-capable command → do NOT hypothesize; say so, list what you tried, ask for env access or a redacted artifact. For flaky bugs, chase a *higher* repro rate (loop 100×, parallelize, widen timing windows). 50% is debuggable, 1% is not.
2. **Harden the repro.** Minimize: cut inputs, callers, config one at a time, re-running after each; keep only what's load-bearing. For input-class bugs, wrap in a property and let the shrinker auto-minimize; store the minimized seed. Bound stress runs (~60s).
3. **Classify.** *Bohrbug* (deterministic) → SBFL → bisect → binary search. *Heisenbug/Mandelbug* (transient, changes under observation) → record-replay / stress; do NOT trust SBFL (flaky spectrum poisons the ranking). *Concurrency* → run the atomicity/order/deadlock checklist FIRST. Scan common patterns (null access, off-by-one, missing await, stale closure, shared mutation, coercion, data-shape drift): ~80% of bugs live here; each match is a candidate hypothesis.
4. **Localize.** *SBFL:* with per-test coverage, rank code by Ochiai `failed(s)/sqrt(totalFailed×(failed(s)+passed(s)))` before spending reasoning. *Bisection:* `git bisect run` across commits; delta-debug the culprit down to the line, or the input to the minimal trigger. *Binary search:* halve the execution path (db→api→serialize→frontend). *Work backwards* from known-good output to the divergence. *Follow indirection:* for constructed paths/keys/URLs, resolve the writer's value and the reader's and confirm they agree. Add observability *before* changing behaviour.
5. **Hypothesize: branch, don't chain.** Generate 3–5 ranked, *falsifiable* hypotheses before testing any ("if X is the cause, changing Y makes it vanish / Z makes it worse"). Actively seek disconfirming evidence: "what would prove me wrong?" Treat your own code as foreign: your implementation decisions are hypotheses, not facts. **When the user is reachable, surface the ranked list before you start testing**: they hold domain context that re-ranks it in an instant ("we just deployed #3", "that path is known-flaky"), and re-ordering is far cheaper than testing the wrong hypothesis first. Skip the checkpoint when running unattended (AFK); never block on it.
6. **Instrument: one variable at a time.** Each probe maps to a specific prediction. Prefer a debugger/REPL breakpoint over ten logs; never "log everything and grep." Tag debug logs with a unique prefix (`[DEBUG-a4f2]`) so cleanup is one grep. For perf regressions, measure a baseline first (profiler, query plan), then bisect; logs mislead here.
7. **Confirm root cause, not symptom.** Enumerate candidate causes across ≥2 categories (code / config / environment / data). Ask the AND-gate: *could this need more than one condition at once?* If yes, a single cause can't account for the symptom: find the co-occurring cause(s); the fix must address all or it recurs. Record confirmed cause(s); append eliminated branches (never delete: auditability).
8. **RCA branching: when a hypothesis fails.** Disproof is progress: move it to Eliminated with the evidence, test the next ranked one. If 3+ fixes failed or you can't explain current behaviour, your mental model is wrong; restart: write what's certain, what's ruled out, generate *new* hypotheses, begin again from reproduction.
9. **Verify the fix.** State the oracle before the assertion (specified > derived/model > metamorphic > implicit-crash; never settle for "didn't crash"). Write the regression test at a correct seam exercising the real bug pattern; if none can exist, that absence IS a finding: flag it. Watch it fail, apply the fix, watch it pass. Then: original repro gone, full suite green, boundary neighbours (N-1/N/N+1, empty/singleton) pass, all `[DEBUG-]` probes and throwaway harnesses removed, winning hypothesis recorded in the commit.
