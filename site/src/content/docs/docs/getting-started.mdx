**Runs on Claude Code and Codex CLI.** trailhead is authored once; the installer projects host-native artifacts. On Claude Code: a skill + `/trailhead:*` commands + hooks. On Codex CLI: a native skill invoked `$trailhead`, one `$trailhead-<verb>` skill per verb for discoverability, and the guardrails as native Codex hooks. Choose the host with `--claude` / `--codex`, or let the installer auto-detect.

## Prerequisites

- An authenticated [`gh` CLI](https://cli.github.com) (the tracker is GitHub Issues).
- A GitHub repo to work in.
- For the npm path, Node 18+.

New to Git and GitHub? Start with [the section below](#new-to-git-and-github).

## New to Git and GitHub?

Already have a GitHub account and `gh` logged in? Skip to [Install](#install).

**The three words you need**

- A *repository* (repo) is the project folder GitHub tracks. trailhead's code lives in one.
- An *issue* is a GitHub to-do item. Every trailhead map and ticket is an issue.
- A *commit* is a saved snapshot of code changes. When trailhead works a ticket, it makes commits linked to that ticket.

**From zero to a working setup**

1. Create a free [GitHub account](https://docs.github.com/en/get-started/start-your-journey/creating-an-account-on-github).
2. Install [Git](https://git-scm.com/downloads) and the [GitHub CLI](https://cli.github.com) (`gh`).
3. Run `gh auth login` and follow the prompts to sign in to GitHub.com. The browser login is the easiest, and letting it set up Git with your GitHub credentials means pushes just work. The prompts vary by version; the [official manual](https://cli.github.com/manual/gh_auth_login) is the authority.
4. Check it worked:

   ```
   gh auth status
   ```

   It should report that you are logged in to github.com with your account.
5. Create a private repo and enter it ([manual](https://cli.github.com/manual/gh_repo_create); or use the [web page](https://docs.github.com/en/repositories/creating-and-managing-repositories/creating-a-new-repository) instead):

   ```
   gh repo create my-project --private --clone
   cd my-project
   ```
6. Start your agent in that folder and continue with [Install](#install), then [After installing](#after-installing).

Step 5 is the explicit route, not the only one: `/trailhead:new` (Codex: `$trailhead new`) in a folder with no GitHub repo offers to create a private one for you.

**Going deeper**

- [Set up Git](https://docs.github.com/en/get-started/git-basics/set-up-git)

## Install

<Tabs>
  <TabItem label="Claude Code plugin">
    Native install, managed by `/plugin`:

    ```
    /plugin marketplace add ToRvaLDz/trailhead
    /plugin install trailhead@trailhead
    ```

    Update with `/plugin update trailhead`; remove with `/plugin uninstall trailhead`.
  </TabItem>
  <TabItem label="npm">
    Installs into your agent's config dir:

    ```
    npx @marcomigozzi/trailhead              # auto-detect the host (defaults to ~/.claude)
    npx @marcomigozzi/trailhead --claude     # Claude Code (~/.claude or $CLAUDE_CONFIG_DIR)
    npx @marcomigozzi/trailhead --codex      # Codex CLI ($CODEX_HOME or ~/.codex)
    npx @marcomigozzi/trailhead --symlink    # dev install (Claude; symlink to the checkout, edits go live)
    npx @marcomigozzi/trailhead --uninstall  # remove everything it added (pair with --claude / --codex)
    npx @marcomigozzi/trailhead --dir=<path> # target a specific config dir
    ```

    On Claude Code it copies the skill (+ its `references/`), the `/trailhead:*` commands, the hooks (into `hooks/`, registered in `settings.json`) including a SessionStart update check, and the label-guard + statusline templates, idempotently.
  </TabItem>
  <TabItem label="Codex CLI">
    `npx @marcomigozzi/trailhead --codex` projects a native Codex skill invoked as `$trailhead` (`$trailhead work`, `$trailhead new "idea"`, …), one thin `$trailhead-<verb>` skill per verb for discoverability, the nine guardrails as native Codex hooks (`~/.codex/hooks.json`, enabling `features.hooks`; the six Bash guards share one process behind a single registration; the search guard is Claude-Code-only and isn't projected to Codex), and per-technique subagent model pins from `models.codex.*` into `~/.codex/agents/`.

    Codex 0.145.0+ is required (the installer gates on `codex --version`). The `artifacts` mockup mode (Claude Code's `Artifact` tool) isn't available on Codex; the cross-host `design: stitch` mode (Google Stitch MCP) is the hosted option there, with local disk as the fallback.
  </TabItem>
</Tabs>

Re-run the install to update, or run `/trailhead:update` (Claude) / `$trailhead update` (Codex) from inside the agent: it detects how trailhead was installed and installs the newer version where that is safe. Release notes are in the [CHANGELOG](https://github.com/ToRvaLDz/trailhead/blob/main/CHANGELOG.md).

## After installing

Restart or reload your agent so the commands register, then run `/trailhead` to start (smart entry), or `/trailhead:new "<idea>"` to chart a map. On Codex the surface is `$trailhead` instead: run `$trailhead` for smart entry, `$trailhead new "<idea>"` to chart, or a per-verb `$trailhead-<verb>` skill.

To let trailhead work a whole map while you are away, see [Autonomous run](/docs/workflow#autonomous-run-auto).

Note: once installed, the commit guard hook runs on every `git commit` (enforcing Conventional Commits and blocking `Co-Authored-By`); disable the plugin's hooks in settings if you don't want that. Either way trailhead is self-contained: no external skill or plugin is required, no preflight, no version drift.
